# Override Re-derivation

How this edition re-derives overrides, exemptions, and script rules when the upstream pin moves, and the traps that are invisible in the code. Read this before resolving the first sync abort.

## The Counted-Swap Method

- Re-derive every stale override from the new upstream text, porting this edition's divergence onto it; never patch the previous override, because unnoticed drift compounds across releases.
- Extract old text blocks from the checked-out submodule with `sed -n` line ranges verified by head, tail, and uniqueness, or scan the release archive in memory with `gh api repos/irootkernel/aquarium/tarball/vX.Y.Z`.
- Replay the differences hunk by hunk in document order, and verify each replacement target occurs exactly once before swapping; a swap whose target count is not one is the wrong swap.
- For script rules, reconstruct the in-file literal from the imported table with per-line `json.dumps(..., ensure_ascii=False)` — em-dashes make ASCII escaping diverge — and require a count of exactly one before replacing.
- Rotate a digest in `overrides/manifest.json` only after the override is re-derived, and rotate a digest in `overrides/codex-exemptions.json` only after re-reading every surviving third-party CLI mention in the shipped file.

## Known Traps

- `references/orca-supervision.md` was the only shipped match of the orca-cli sigil rule until v0.1.14 gave that rule a second match in `orca-review/SKILL.md`; v0.1.19 deleted both files when Herdr Review replaced Orca Review, and the rule and its needle retired with them. Recount before assuming a new override is safe: a rule whose last shipped match moves inside an override target is dead from that run on.
- The create-prefixed sigil rule counted exactly one shipped match while its occurrence in `agents-guidance.md` was override-shadowed. v0.1.21 retired that override, so the rule now matches twice — in `references/podway-integration.md` and `skills/dev-setup/references/agents-guidance.md` — and overriding either file would drop it back to one. Retiring an override also exposes its upstream text to every rule, needle, and sigil scan, which is where the lore-query and the two humanize sigil rules came from, so recount in both directions.
- The task-close closeout rule stays ordered before the generic input-tool substitution because its anchor contains the generic needle, and the generic rule survives on a single `docs-setup` match.
- Upstream's launcher-matcher helpers ship defined but uncalled, pinned by the validator's no-caller list; recheck the pins on every adoption.
- The `independent-review` override reached across skill directories for the repository-state inspector until upstream deleted it in v0.1.14, so the edition owns that inspector as an addition under the skill that runs it. v0.1.20 renamed `independent-review` to `subagent-review` without an alias and the inspector moved with it to `skills/subagent-review/scripts/`; `tests/validate.rb` asserts that it ships, that the skill still takes and compares the baseline, and that the skill names no retired skill directory.
- Any host tool this edition names in replacement text is its own to retire if the harness renames that tool; the upstream anchor keeps matching either way, so no abort will surface it. The subagent dispatch tool was renamed once already, which is why the release-qa rule names the mechanism instead of the tool, and v0.1.15 retired the TodoWrite naming rule when upstream made the sentence host-neutral on its own.
- The sigil scan assumes every lowercase dollar-prefixed name in Markdown is a skill invocation, which v0.1.14 broke with the shell variables in `task-commit`'s `git -c` snippet. Name each new false positive in `SIGIL_LITERALS` rather than narrowing the pattern, and mirror it into `tests/validate.rb`, which compares the two lists as sets. The scan covers additions too, so an unlisted sigil-shaped token written into this file or any other addition stops generation just as an upstream one would.
- Invocation gating is upstream's decision, not a fixed set: v0.1.14 opened `orca-review` to implicit invocation, v0.1.18 opened `dev-setup`, and v0.1.19 removed `orca-review` while opening the new `herdr-review` and the goal judge that v0.1.20 renamed `goal-evaluator`, so at v0.1.21 the model-invocable set is `dev-setup`, `goal-evaluator`, `herdr-review`, and `task-commit`. Read the set from the sidecars on every adoption instead of asserting a remembered one; a skill that changes sides also gains or loses the delegation note.
- The generated-script gate parses and checks call arity only, so block rules must swallow every downstream reader of the locals they delete; the MCP-inspection unit tests are the only executable coverage.
- The bundled reviewer subagent has no digest gate against the skill and contracts it serves: the `subagent-review` override's digest stops the sync when upstream's skill changes, but the review, intent, and strategy contracts now ship as upstream writes them and stop nothing. Re-read the agent against all of them whenever upstream changes any one.
- `README.ko.md` has no automated agreement check with `README.md`; mirror every change by hand and re-read both.
- Nothing checks README prose against the artifact, so a skill split silently invalidates it: v0.1.15 moved Ouroboros, Deslop, and Lora into `dev-setup-global` while both READMEs still named `dev-setup`. When upstream moves a capability between skills, grep both READMEs for the skill that lost it.
- A forbidden needle written the way prose spells a path misses the way Python spells it. The needle for the shared cross-agent skills root carried a leading tilde, which the `Path.home()` form upstream writes in Python never contains, and v0.1.15 wrote eleven of those into a new trust table plus the Lore and Deslop readiness comparisons — every one a path this host can never produce. Prefer the spelling both languages share, and when upstream hard-codes a root, check the scripts as well as the prose.
- A block anchor whose first line is still present can still be stale: v0.1.15 left every dead script rule's opening line in place and changed the lines around it. Six Ouroboros block rules were collapsed into one whole-function rule for that reason, which is the more stable anchor upstream offers and fails loudly instead of drifting.
- An override earns its place only while the divergence is semantic. v0.1.15 moved user-global installation out of `dev-setup`, leaving three literal spans, so that override was retired and replaced by counted substitutions — verified by proving the rules reproduce the retired override byte for byte before deleting it.
- The hard-wrap convention is this repository's, not upstream's: v0.1.15 shipped two hard-wrapped references, so the check covers authored Markdown and the override and addition sources rather than the generated tree.
- A probe-shape change upstream kills every rule that reads the probe at once: v0.1.16 replaced `named_mcp_server_missing` and the raw stderr prose with a `presence` key that only `mcp_registration_probe` sets, and six script rules died in one release although only one behavior changed, with two more dying when upstream hard-coded the shared skill root in `inspect_im_not_ai` and the trust table. Anchor on whole functions and, when a helper's return shape changes, recount every rule that consumed it.
- A helper added in one module and called from another moves a rule across modules: v0.1.16 moved the user-scope MCP probe from `inspect_global_tools.py` into `inspect_tools.py` as `inspect_global_mcp_scope`, so the rule that rewrote the global inspector's function was retired and the project inspector's new function became the anchor. Check both sides of every cross-module call the validator pins.
- When upstream disables a capability this edition implements differently, the files this edition does not override inherit the disabled framing: v0.1.16 wrote a run of "disabled" and "if re-enabled" sentences into three shipped files this edition had not overridden, two of them behind the anchors of existing rules; the new intent contract's whole routing section made that file an override, and the four sentences in the disposition contract and `orca-review` became substitutions. v0.1.17's new routing contract repeated "Independent Review remains disabled", so inventory those sentences in new files as well as changed ones before choosing between substitution and override. Upstream then converged on this edition's design — v0.1.18 ran Independent Review on fresh host subagents and v0.1.20 renamed it Subagent Review — so at v0.1.21 every one of those rules died and was deleted, and the review overrides retired with them.
- An upstream hunk that spells the other host's name must never be copied verbatim into the exempt catalog override: the exemption records that a human read every remaining mention as third-party, and v0.1.16's Sanho, Gaori, Mulgae, im-not-ai, and Ouroboros hunks all name that host. Port the fact, not the sentence, and re-read the mention list before rotating.
- A wholesale plugin-root exclusion hides whatever upstream adds under it: v0.1.17 added its production status runtime as a second tool beside the excluded development channel under `tools/`, with no abort, and the only signs were an in-process loader in the global inspector and the skill prose. Generation and the validator now reject any generated reference into a child of an excluded plugin-root directory, and the runtime's and its specification's names are forbidden needles.
- Excluding an upstream feature is not finished at its skill. v0.1.17's `status` skill reports a ledger whose runtime sits under the excluded `tools/`, and upstream wired that ledger into `dev-setup`, `dev-setup-bundle`, and the global inspector, so the exclusion took `EXCLUDED_SKILLS` for the skill, deletion substitutions paragraph by paragraph in every consumer, and script rules for the inspector's loader. Remove an excluded skill before the text rules run, or its sigils keep otherwise dead rules alive, and never exclude one file by file: `transform_skills` refuses a skill directory without `SKILL.md`, and a basename check on `SKILL.md` matches every skill.
- Route IDs and Podway Procedure labels are byte-canonical: Podway compares installed Procedures with the bundled bytes, so v0.1.17's `native-codex` route ID and the labels that spelled the other host's name in three Procedures shipped as upstream wrote them, behind a `CANONICAL_PHRASES` tolerance that masked only those phrases inside the Procedure assets. v0.1.21's Procedures no longer spell that name — the route is `subagent-review`, and `native-codex` survives only as a historical identity in the routing and Herdr migration references — so the tolerance, its gate, and its validator mirror retired, while the validator still asserts every bundled Procedure byte-identical to upstream. If a canonical label ever spells a forbidden needle again, mask the phrase inside its scope rather than exempting the file, and run every rule whose anchor contains it before any generic rename.
- Re-derive a script rule from the new upstream function, never from the old replacement: v0.1.17 renamed `*_SUPPORTED_RELEASE` to `*_MINIMUM_VERSION` and `supported_release=` to `minimum_version=`, so a ported replacement would have shipped a NameError only the unit tests see, and it moved the writing-skill root choice into two helpers that go with their last callers. A replacement can also contradict upstream's own check: the Ouroboros `supported_range` still said `<0.54.0` after upstream dropped the cap.
- Anchors inside hard-wrapped upstream files carry their exact line breaks, while the replacement text lives in Python, where the one-line-paragraph check cannot see it; write each replacement paragraph on one line by hand.
- Host tools can depend on the session's model. Claude Code gives its todo and task tools by default only to older models, not to Fable 5.1 or Opus 5.5, which is why v0.1.17 moved this edition's mapping of upstream's host goal from a todo list to the session `/goal`. Map a host capability onto something every supported model has, and check who can drive it before choosing which verbs a substitution keeps: the user sets or clears `/goal`, an evaluator ends it once it holds or is impossible, and the model can propose one only through a `ProposeGoal` tool that a feature flag keeps off by default. `/goal` is now a host name this edition owns and must retire if the harness renames it.
- Claude Code ignores `permissionMode`, `hooks`, `mcpServers`, and `initialPrompt` on plugin subagents, and `claude plugin validate --strict` stays silent, so a plugin agent's frontmatter can claim a restriction or behavior it does not have; the validator rejects those keys.
- A subagent without an explicit model inherits the session's, and the subagent mechanism offers only the `sonnet`, `opus`, `haiku`, and `fable` aliases. It has accepted a per-invocation effort since Claude Code 2.1.292, but withholds that setting while `CLAUDE_CODE_EFFORT_LEVEL` fixes every effort in the session; an earlier version of this note said no per-dispatch effort existed, which was wrong. Name the model wherever this edition's text dispatches a subagent, keep Opus as the baseline, leave Fable to an explicit user request, and have text that promises a requested effort say so and stop when the setting is unavailable rather than run at the session's effort.
- Relative links that climb out of the plugin, such as v0.1.17's links from the setup skills into upstream's repository-level `docs/specs/`, resolve into this repository instead of upstream's and dangle here; those went with the ledger paragraphs, but check every new one.
- Upstream skills delegate to each other by name, which the other host treats as an explicit invocation, but Claude Code's Skill tool refuses a skill gated by `disable-model-invocation` unless the user typed its name in the current turn, always refuses it inside a subagent, and forbids carrying out the refused workflow any other way, so every hand-off into a gated skill used to stop the workflow. `DELEGATION_NOTE` resolves it without opening the gate: generation puts it directly under the title of every gated upstream-derived skill, overrides included, and it routes a hand-off through the delegated skill's `SKILL.md`, read in full or given to a subagent by absolute path, whether the text writes the slash form or names the skill bare as Podway node guidance does. Model-invocable skills carry no note, because Claude can start one on its own and its hand-offs into gated skills must keep going back to the user, so a sidecar that flips a skill's invocation policy moves it in or out of the note; and the note tells a hand-back — a continuation request, routed repair, or recommendation the text returns to the user — apart from a delegation, because the refusal used to be what sent those back. The note is placed by generation rather than by per-site rules, so a delegation upstream adds needs no rule, and releases after v0.1.17 add more; a body that stops opening with its title stops generation, and whatever accommodates such a body must still put the note before any instruction, because a refused Skill tool call cannot be undone by reading on. The note names the host's Skill tool, and so do the two ordinary-orchestration rules that hand a subagent the owning skill's path, so a rename of that tool retires all three wordings with no abort to surface it, the same class of trap as host tool names in replacement text.
- An alias-less upstream rename kills the override target, the argument hint, and an addition directory at once. When v0.1.20 renamed `independent-review` to `subagent-review`, the override gate stops on the vanished target and `transform_skills` on the hint for the missing skill, but `apply_additions` would recreate the old skill directory around the repository-state inspector with no `SKILL.md`, and neither generation nor the validator notices an addition left under a vanished skill. Move overrides, hints, and additions together, and list the generated `skills/` directories after the run.
- A dead block rule whose sibling stays alive can bind arguments to the wrong parameter while passing the arity gate. v0.1.18 appended a Sorage upgrade-preflight flag to `inspect_global` after its two per-home parameters, which killed the signature rule at the v0.1.21 adoption while the call-site rule kept dropping those two arguments, so deleting the dead rule would have bound the fifth positional argument — the flag — to the first per-home parameter, within the accepted count, and the Sorage probe would never have seen it. The re-derived signature keeps the flag fifth and a unit test pins the binding; re-derive a dead signature rule against every live rule that edits its callers.
- Upstream convergence is a reason to retire overrides, not to re-derive them. v0.1.18 through v0.1.20 rebuilt upstream's review on fresh host subagents, the design this edition's Independent Review override had carried since v0.1.14, so v0.1.21 retired the review-contract, review-intent, and Independent Review overrides, deleted the fourteen review-stack rules whose text upstream removed, and kept only the divergence that remained: one skill override for this host's bundled reviewer, model and effort handling, and repository-state baseline, and literal rules for the rest. Before re-deriving a stale override, diff upstream's new text against it and ask whether a few counted swaps now say the same thing.
- Digest-pinned data must ship verbatim, and its reverse imports must be pinned. v0.1.20's adaptive known sources record the SHA-256 of every bundled Procedure, and its capability signatures and operation contracts pin canonical JSON, so `assets/adaptive/` and `assets/schemas/` are `VERBATIM_DIRECTORIES` that every scan still reads but no rule rewrites; `shared/` imports names from `inspect_tools.py` and the Goal Evaluator's `ordinary_assignment.py`, which script rules may rewrite. The validator asserts all three trees byte-identical to upstream and pins each imported name, because a renamed one would pass the parse and arity gates and fail only at run time.
- Trigger phrasing in skill descriptions is upstream's. The validator once required every description to say "Use when", which held through v0.1.17, but v0.1.18 through v0.1.21 wrote several without it — `goal-evaluator` and `task-commit` among them — and upstream's own validator never checked it, so the check now requires only a non-empty description. Do not encode an upstream prose habit as an invariant of this edition.
- Never spell the Herdr skill's dollar-prefixed sigil in an addition, even to describe its rule: the forbidden needle and the sigil scan read additions too, so write `/herdr`, the slash form the substitution produces.

## Verifying a Re-derivation

- Generation is the first gate: every substitution rule must match text that ships, and a rule whose only matches are override-shadowed is dead.
- A new sigil family needs its forbidden needle added to both the Python table and the Ruby list, which the validator compares as sets; a needle added to one side alone reports healthy.
- A full-file override passes every gate as long as the generated tree matches it, so nothing proves it ported every host-neutral sentence upstream added. After re-deriving one, diff upstream's release delta for that file against the override sentence by sentence, and give every dropped sentence a reason the README override table records.
- After the five validation commands pass, prove gating live: a `claude --plugin-dir plugins/aquarium -p` listing must show exactly the skills whose upstream sidecars allow implicit invocation, and no others. Read that set from the sidecars rather than from a remembered count.
