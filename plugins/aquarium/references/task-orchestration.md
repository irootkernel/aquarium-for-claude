# Task orchestration

The [adaptive execution contract](adaptive-execution.md) now selects adequate definitions and resolves current mapped placements for this family. The canonical node tables below retain their original meanings; adaptive dispatch uses actual role, capability, evidence and approved due ownership rather than node spelling. Original review, independent assessment, effect and acceptance boundaries remain due.

## Ordinary execution

Task version `34` uses ordinary Actions and the [v3 role and evidence contract](ordinary-agent-orchestration.md).
Use the Coordinator harness's supported native Executors and independent report-only Evaluator without prior qualification, role snapshots or configuration digests; on Claude Code, dispatch them as subagents with the `opus` model unless the user names another, as the [ordinary contract](ordinary-agent-orchestration.md) directs.
Actual original criteria, current candidate, checks, authority and available
public handles remain necessary. Existing formal sessions retain their original
[formal v1 contract](formal-agent-orchestration-v1.md) and supported released continuation.

## Planning and phase progression

Before a session, a read-only `task-plan` Executor proposes the plan. The Coordinator
obtains actual approval. `plan-only` ends there.
After approval and session admission, revalidate the exact approved artifact
against the current record-plan inputs without inventing formal acceptance.

The plan reads applicable guides, declared adoption coverage and original
canonical sources under [directory agent guidance](directory-agent-guidance.md).
The existing documentation delivery maintains affected canonical content, guide
links and local instructions before final prose passes and review. Its Evaluator
assesses those due obligations with the complete candidate. Guide absence alone
adds no prerequisite, and delivery does not implicitly expand adoption.

| Work or Coordinator evidence record | Independent Evaluator | Coordinator Decision |
| --- | --- | --- |
| `record-plan` | `evaluator-plan` | `decide-plan-assessment` |
| `implement`, `refine`, `verify` | `evaluator-verification` | `confirm-verification-operation`, then `decide-verification` |
| `document` | `evaluator-documentation` | `decide-documentation-assessment` |
| Admitted `review` evidence | `evaluator-review` | `confirm-review-completion` |
| `prepare-task-assessment` | `evaluator-task` | Applicability confirmation, then `assess-goal` |
| `prepare-stopped-task-assessment` | `evaluator-stopped-task` | Applicability confirmation, then `assess-stopped-goal` |

The Coordinator retains all Decisions and operational records. Evaluator Actions have no
recursive Evaluator. Executor Actions return `aquarium.executor-handoff/v3`; Evaluator
Actions return `aquarium.evaluator-assessment/v3` with all original criterion rows.
Final assembly records the Coordinator candidate-evidence index instead of an Executor handoff.
Record their exact artifact metadata and retain complete bytes outside Podway.
Podway stores caller assertions and metadata; it neither authenticates records
nor establishes semantic truth.

For each ordinary Action, read complete current inputs and selected evidence,
receive the actual result, check scope and authority, then record the work and
complete with current Podway fences. Executor delivery is not semantic passage.
The Coordinator checks the independent Evaluator report and uses its current assessment
without another Evaluator cycle for report acceptance. Final assembly is bookkeeping;
reuse an existing complete final report only with verified current coverage,
candidate, requirements and checks. Corrections require fresh affected assessment.

A phase pass requires current applicability and a passing `evaluator-checkpoint-result`
for all actual due phase obligations and applicable parent constraints. Retain
every original global criterion row, verdict and unmet/unverified count; later
work can remain a global gap. A plan checkpoint proves the exact approved plan,
implementation proves its due implementation obligations, and verification proves
required checks. Review evidence preserves faithful negative provider rows and
their original completion, severity and Low routing. Report completeness alone
cannot establish implementation, correction or verification success. Executor-only
delivery, omitted original criteria, absent
reports, changed targets, stale requirements, missing required candidate evidence and
inconsistent reports block passage. Return disputed or inapplicable assessments
to the retained Evaluator with original conflicting evidence. An unchanged artifact
still needs current artifact and check revalidation after rework.

Established gaps and missing evidence use separate checkpoint-local followup
records. The implementation/refinement/verification group selects its earliest actual
owner (prepare-implementation, refine or verify). Before returning, its authority gate requires a passing
caller-supplied result for the exact existing grant, effect, target and owner.
A negative verdict grants no new effect, review ordinal or provider operation.
If another earlier phase owns the change, use its already authorized manual
rework target and retain the source attempt, report, target, criterion and
consumption basis. Never route forward around a required phase. Missing native
or evidence authority remains a blocker. Evidence collection uses its actual
owner and reconciles an existing provider operation before any new dispatch.

## Review, final assessment and closeout

Keep selected technical evidence and Evaluator assessments distinct. Route binding,
operation admission, ordinal, evidence, provenance, finding confirmation and
backend checks still precede `evaluator-review`. A failed backend check retains its
existing correction-authority path. Evaluator-owned negative completion first classifies eligible local corrections.
Nonlocal unmet completion enters `record-task-rework-basis` and the existing
serial authority and phase-owner chain; missing evidence retains its dedicated
review evidence/authority path.
Preserve original provider completion rows, frozen findings, accepted risks,
Low dispositions, review mode and every consumed ordinal. An Evaluator never counts
as a technical reviewer or permits another review by itself.

The Coordinator assembles original phase, review and Evaluator reports and applicable
Task and parent criteria in its final evidence index. Include branch-specific Low and stopped records when
present. The graph selectors provide current core and report references. The index
must also supply the remaining original evidence in full. Its summary cannot
substitute for those bytes. No new implementation, broad audit or provider
review occurs during assembly. Local-settlement composition retains the reviewed basis, verified permitted
delta, exact after-target, current criterion evidence and honest coverage limit;
ordinary Low-only settlement carries unaffected source rows unchanged. Do not consume a new review ordinal for that delta.

`achieved` requires the final applicable Evaluator pass, zero mandatory gaps and the
Evaluator's exact achieved outcome. Explicit stops retain their structural exclusion
of achievement. Negative outcomes do not authorize success status or reopening
stopped work. Actual task-close approval and the exact separate task-commit grant
remain required. Direct phase invocations retain their existing authority;
when the handler delegates a phase, the Coordinator owns approval conversations,
Podway acceptance and progression.

## Verification limits

Structural and synthetic tests do not prove installed native execution. Verify
actual startup, failure, rework and public-handle recovery separately; every
installation-dependent check follows the target repository's verification
environment policy. Preserve unknown outcomes and settle mutating Executors before
replacement. Actual overall acceptance and
managed rollout retain their separate authority.

After admitted review evidence, apply the [local-settlement contract](finding-disposition.md#decide-whether-a-correction-needs-another-review) before provider-rework authority. Preserve source negative rows, verify the exact correction and current criteria, then supply the complete composition to the required final Evaluator. `confirm-local-corrections-settled` checks pending repairs before ordinary Low completion. Native backend failures and missing reviewer coverage retain their existing gates.

For unexpected missing topology in a running session, use the shared [consented atomic supersede](adaptive-execution.md#consented-atomic-supersede) after reconciling pending effects and retaining the qualified successor. Preserve history, original findings, review ordinals and remaining grants. Declared rework, same-operation result retrieval and an approved normal successor remain under their existing authority; a missing report alone never warrants replacement.
