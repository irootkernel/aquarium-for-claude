# Review result handoff

Use this contract when collecting or forwarding review results and sending
correction responses in the next authorized Brief. Apply it at
specialist-to-main, main-to-owner and owner-to-next-phase boundaries. The native
tool and paired skill own transport syntax and recovery.

## Use the actual result surface

| Route or transport | Producer and consumer responsibility |
| --- | --- |
| Mulgae | Mulgae owns generation, storage, publication and retention. Aquarium preserves returned invocation/run references and reads complete reports through supported receipt-bound API or CLI reads. Native publication state and receipts establish available production facts; no extra file, export or private runtime inspection is required. |
| Subagent Review | Each subagent returns its report through its native delegation. Collect from that exact handle, including every expected base and UI reviewer. A separate Markdown file is not implied. |
| Herdr | The main reviewer collects children's reports and synthesizes the result. The caller reads that same main agent through native output. Expand an incomplete read; use the same-reviewer file fallback only to recover an existing result. |
| OS pipe or captured output | Use an advertised CLI/wrapper interface. Identify writer, reader and payload channel; distinguish result content from diagnostics according to that interface. Successful exit or write does not establish that the receiving consumer read a complete result. |
| Temporary file | Where native delivery permits it, the producer finishes and reads back its own output, returns the actual absolute path, and the consumer opens and reads it in its own filesystem view. A printed path is neither creation nor receipt. |

A path transmits a locator, not its contents. Check recipient access; otherwise
use an already supported content/reference interface within transmission
authority. Do not invent stdin/file-input flags or require files for all routes.

## Establish delivery from existing observations

Distinguish production, submission and recipient readback. A completed agent
state, start acknowledgement, excerpt or process exit is not a complete report.
Read every required page or chunk through native continuation, retaining its
receipt and identity where provided. Associate content with the requested
operation, target and participant and collect the expected report set. This
establishes delivery, not the truth of the conclusions.

Record bounded transport and producer/consumer observations with exact native
references or a reference to the inline response in existing runtime handoffs.
For files, retain actual location and relevant environment. Preserve unavailable
observations explicitly. The consumer's existing read supplies readback; do not
add an acknowledgement turn, receipt schema, central store or synthetic hash
prerequisite. Keep report prose in its permitted native/temporary surface;
bounded orchestration records retain references under
[evidence residency](evidence-residency.md), not copied raw provider payloads.

## Agent-owned temporary files

Follow the target repository's temporary-file guidance and use a unique owned
directory. If that guidance prefers a mounted volume, verify the actual mount
and write access before creating files there; directory existence alone does
not establish a mount. Otherwise use the system temporary directory. Aquarium
does not impose a universal temporary path on its consumers.

Return the completed file's actual absolute path through the supported
interface. Handle spaces and non-ASCII characters correctly. The receiver
checks accessibility in its environment; do not assume a shared cwd, machine
or filesystem view. Keep agent-owned delivery files until their intended
consumer reads them, then apply cleanup policy to those files only. Native
artifact retention remains native-owned.

## Recover delivery before repeating review

A missing file, truncated output, failed read or lost reference is first a
retrieval incident. Preserve the operation and use supported result queries,
existing delegation handles, expanded reads or permitted re-emission of the
same completed result. Herdr's fallback asks the same reviewer to save its
existing result after expanded native reads cannot recover it. This requests
delivery, not another assessment.

Do not infer a run from `latest`, search unrelated temporary directories, read
private provider logs or dispatch another reviewer to recreate delivery.
Repeated retrieval and provider-free recovery preserve findings and ordinals.
When available native paths establish that required content is unrecoverable,
report the precise gap under the existing lifecycle contract. A fresh review
still needs its independent reason and authority. Missing evidence cannot be
relabeled as a complete review.
