# Task Handler

> **Claude Code delegation:** when this skill, or a reference or Procedure node it follows, hands a step to another Aquarium skill — however it phrases the hand-off, and whether it writes `/aquarium:<name>` or names the skill bare — read that skill's `SKILL.md` in full from this plugin (`../<name>/SKILL.md` from this skill's directory) and follow it as the delegated step instead of calling the Skill tool. Claude Code reserves most Aquarium skills for the user to type: it refuses the Skill tool for them and, once it has refused, forbids carrying out their workflow any other way. When you hand such a step to a subagent, put that file's absolute path in its assignment and have it read the file, because a subagent cannot load a gated skill through the Skill tool. Running another skill's bundled script is not a hand-off. A continuation request, routed repair, offer, or recommendation that the text has you return or report to the user is not a delegation: name its slash command, do not run it yourself, and stop where the text stops.

Read [commit-attribution.md](../../references/commit-attribution.md) for message formatting and change origins, within this skill's existing effect boundaries.

Read [review-routing-contract.md](../../references/review-routing-contract.md) for route selection, route-specific readiness, evidence combinations, recovery, and assessment ordinals. Read [review-intent-contract.md](../../references/review-intent-contract.md) for the shared Review Brief and criterion-level completion assessment. Read [mulgae-review-contract.md](../../references/mulgae-review-contract.md) only when the selected review route is `mulgae`.

Strengthen execution of one roadmap task goal with focused phase skills. Own task identity, authority, goal lifetime, transitions, resumption, and final evidence. Select `execute` by default, `plan-only` for a non-mutating plan, `plan-handoff` only when another agent will continue, and `resume` for continuation. Treat "plan only" as `plan-only`; for `plan-handoff` or its resume, read [plan-handoff.md](../../references/plan-handoff.md) and follow it.

Always read [evidence-residency.md](../../references/evidence-residency.md), [finding-disposition.md](../../references/finding-disposition.md), [release-notes.md](../../references/release-notes.md), and [epic-execution-sot.md](../../references/epic-execution-sot.md). On the Podway path also read [procedure-node-contracts.md](../../references/procedure-node-contracts.md). Use Podway by default. A pre-session user opt-out or higher instruction excludes it; then do not inspect Podway, load `/use-podway`, read [podway-integration.md](../../references/podway-integration.md), or carry the opt-out forward.

Otherwise read the Podway contract, use one adequately selected Task-family session for this canonical task after plan approval, coordinate with an explicitly authorized Claude Code session goal under the shared Podway contract, and record each verified phase handoff at the matching node. In `plan-only`, create neither goal nor session; in `plan-handoff`, create the session only after approval, work under a Claude Code session goal only when the user sets one, and stop at its mapped first-work boundary with the verified plan artifact. Do not let either goal mechanism or runtime evidence replace roadmap authority.

No role-snapshot or native telemetry qualification is required. Existing formal snapshots retain their admitted v1 integration and receipt contract.

## Settle corrections before requesting another review

Classify the complete current issue set first. Local settlement is available only when every current blocking obligation is locally eligible; a mixed nonlocal set keeps its original rework, confirmation or user-direction route as a whole, including the complete frozen finding and criterion set. Apply [finding-disposition.md](../../references/finding-disposition.md#decide-whether-a-correction-needs-another-review) before treating priority or a negative completion row as a provider-rework obligation. A `local-verified-fix` keeps its effective priority and is corrected and verified within the existing envelope without another approval or provider ordinal, including in confirmation-only mode. Preserve the original review and criterion rows, then bind current completion to the exact locally verified delta and the required final Evaluator assessment. Execution incidents follow [review-contract.md](../../references/review-contract.md#reviewer-instruction-deviations); preserve usable evidence and repair only the affected guarantee under existing authority. When another provider assessment is genuinely required, run it on the selected route within the remaining grant without asking again. Only uncovered effects or exhausted necessary review authority require new approval.

## Establish the Task Contract

Require one mutable Git repository or a working directory inside it, one canonical roadmap path inside that repository, and exactly one task ID present in that roadmap. Reject epic-level requests, multiple tasks, requests without one canonical roadmap task identity, non-Git work, and external roadmap paths. Normalize an ID only when repository instructions define the rule.

1. Resolve the Git root and read every applicable instruction file.
2. Read the roadmap entry, complete parent-epic membership, `docs/README.md`, roadmap and canonical-document links, role owners, required artifacts, and any linked active dossier. Resolve the requirement-bearing canonical document set instead of asking the user. Use the dossier when one exists. When no dossier is declared, assemble the shared composite execution SOT and disclose its source paths and requirement owners in the plan. A declared dossier whose link cannot be resolved is a semantic gap, not dossier absence. Stop and route revision to the appropriate work-definition skill when an exact semantic requirement is missing, ambiguous, or unowned. A Task applies no dossier creation threshold and needs no dossier waiver.
3. Inspect branch, upstream, staged, unstaged, untracked, and conflicted state. Separate task-owned work from pre-existing work. Resolve whether Project Configuration declares one release-notes authority and record its open target or structural gap without inventing enrollment.
4. Discover repository-native build, verification, documentation synchronization, Gaori, `/use-gaori`, Sanho, `/use-sanho`, Lore guidance, and the upstream `/deslop` skill when refinement is actually due. Recommend one completion-review route under [review strategies](../../references/review-strategy-contract.md) from the original goal, scope, difficulty, impact and uncertainty. Present the reason for selection through the existing plan approval, preserving an explicitly chosen route or waiver. Record the exact target scope, explicit Herdr reviewer when applicable, and explicit waiver authority and assurance limit when applicable. Discover only the selected route's prerequisites and treat each CLI, repository configuration, project MCP, and agent skill as independent state.
   On the adaptive path, require the upstream `/deslop` installation only when actual code/test changes or an independent repository rule make refinement due. For the canonical/direct phase path, require one valid upstream `/deslop` installation before plan approval; if it is missing, duplicated, symlinked, lacks the upstream LICENSE, or has invalid frontmatter, stop before implementation and return an exact `/aquarium:dev-setup-global` continuation request naming this repository, roadmap, task ID, `deslop`, and the observed installation gap. Never substitute an Aquarium-owned copy, inline reconstruction, or skipped cleanup pass.
5. Record authority already granted for mutation, staging, review, commit, amend, push, PR changes, provider use, and destructive actions.
6. Route a missing or unhealthy global CLI, paired skill, service, or global MCP prerequisite to an exact `/aquarium:dev-setup-global` continuation request. Route repository configuration, project MCP, binding, workspace, or managed-Procedure readiness to `/aquarium:dev-setup`. Do not classify a healthy conflicting Procedure v2 session as a setup prerequisite, and do not install or initialize tools here.
7. Honor an explicit pre-session opt-out without Podway discovery. Otherwise apply the shared contract's readiness and session checks. On degraded readiness, route a missing or unsupported global Podway CLI or `use-podway` skill to `/aquarium:dev-setup-global`; route repository configuration or managed-Procedure gaps to `/aquarium:dev-setup`; then stop and ask the user to choose the exact routed repair or an explicit opt-out for this task.
   - A matching recoverable session becomes part of the plan. Only when starting a different session, present the existing session and obtain the shared contract's explicit preserve, lifecycle, delete, or eligible-replace choice. Never route by skill owner or describe the choice as setup repair.
   - A disposed terminal session with verified handoff evidence and a current `session.start_replace` template becomes an exact successor candidate. Disclose its automatic archival in this task's envelope and, after approval, execute the template's current plain `start` argv without a separate reset before re-observing and beginning the prepared task session.

In a Sanho-managed repository, record whether `/use-sanho` is available. If repository guidance requires it and it is missing or invalid, route an exact `/aquarium:dev-setup-global` continuation request. Otherwise keep it optional and let the document and close phases apply the repository's fallback Sanho guidance at their actual Git boundary.

When repository guidance selects Gaori, read [gaori-integration.md](../../references/gaori-integration.md) and use its prerequisite routing. The verification phase owns the command and acceptance criteria; `/use-gaori` owns native execution.

For `mulgae`, record whether `/use-mulgae`, the supported configured CLI, and the attached project MCP are available; route a missing or invalid skill or CLI to `/aquarium:dev-setup-global`, and a required repository config or project MCP gap to `/aquarium:dev-setup`. For `herdr`, require `/aquarium:herdr-review`, the separately installed upstream `/herdr` skill, the explicit reviewer kind and requested native model/effort, a complete isolated staged Task target, and selected-route caller readiness under [herdr-supervision.md](../../references/herdr-supervision.md). Check `HERDR_ENV=1` before session inspection or control; a missing context blocks Herdr only and does not create a replacement session. For `subagent-review`, require `/aquarium:subagent-review`, the expected fresh host reviewer team, and support for any explicitly selected model and effort. For `waived`, require explicit delegated-review waiver authority and no backend readiness. A prerequisite gap blocks only its selected route and returns to route selection; it never starts another route automatically.

Repository and system instructions override this workflow. Invocation plus plan approval authorizes only the selected task-scoped review route, shared-policy finding remediation within the approved task, affected checks, task-owned staging, exact restaging of already staged affected paths, and an approved lifecycle edit. It excludes an automatic route change or waiver, commit, amend, push, PR changes, destructive commands, undisclosed source transmission, unplanned files, and unrelated staging. Hand an authorized commit to `/aquarium:task-commit`.

Do not start or mutate Podway before plan approval. The plan discloses the selected review route, target scope, route-specific reviewer or waiver authority, session start or resume, the separate fenced `begin`, evidence, decisions, route recovery, rework, goal assessment, completion, and supported disposition. The selected route remains effective until an explicit bounded change. The plan also names any downstream consumer and approved `repository-required` or `external-handoff` promotion; otherwise task promotion is unavailable. `plan-only` stops without mutation. `plan-handoff` additionally discloses the temporary plan, attachment, session stop, successor propagation, resume report, and cleanup.

Approval explicitly omitting Podway approves the plan without those operations. Accept opt-out only before the first managed-session mutation. Afterward classify every stop or opt-out request through the shared `Handle In-Progress Stop Requests` flow; never assume pause, cancel, reset, or an in-place switch to non-Podway execution.

## Load Phase Skills in Order

For an admitted adaptive Task, resolve only the actual due phase owners from the approved work and mapped current placement under [adaptive execution](../../references/adaptive-execution.md#consume-mapped-current-work). Read each selected installed leaf skill completely before its work. Keep independent grouped assessments and all due postconditions; do not require unused phases.

For the existing canonical or admitted legacy path, resolve every phase skill from the installed Aquarium plugin, read its complete `SKILL.md`, and follow it in this exact order:

1. `/aquarium:task-plan`
2. `/aquarium:task-implement`
3. `/aquarium:task-refine`
4. `/aquarium:task-verify`
5. `/aquarium:task-document`
6. `/aquarium:task-review`
7. `/aquarium:task-close`

Treat a missing phase skill as a broken plugin installation. Do not silently inline, reconstruct, reorder, or substitute its workflow.

Immediately after plan approval and before implementation, re-read the task lifecycle vocabulary; in `plan-handoff`, defer this roadmap edit until `resume`. Preserve `In Progress` or `In Review`. For a terminal task, ask whether to reopen it through a roadmap-defined active state and stop without approval. Otherwise change it to `In Progress` only when that exact state is defined; when absent, preserve the current status. Verify this task-owned edit before loading `/aquarium:task-implement`.

## Own Goal Lifetime

Work under a Claude Code session goal only after plan approval and only when the user sets one. When the user asks for one, give them the exact `/goal` condition naming the task ID and evidence boundary, and tell them that setting it replaces any different goal already active, because a session holds one goal at a time. Otherwise proceed without proposing a Claude Code session goal.

When the user has set a Claude Code session goal, keep working toward it through every phase. Report it met only after `/aquarium:task-close` succeeds, any selected Podway finalization is verified, and no required task work or authorized lifecycle action remains. Report it unreachable only when the same unresolved external blocker persists across consecutive turns with no authorized action remaining, because the `/goal` evaluator may then end it as impossible; otherwise keep working and report the exact gap.

## Resume Without Shadow State

Do not create or read `.aquarium` or another orchestration state file. On continuation, reconstruct progress from the named roadmap, current Git index and worktree, goal state, repository-native documentation state, verification evidence in the conversation or repository, and the selected route's evidence and finding lineage. When Podway is active, its latest native observation envelope (`podway.observation-result/v5`) is also required reconstruction evidence.

Treat bounded readback previews as metadata; retrieve each selected complete value through digest-bound evidence-read pagination, and re-observe and restart when a page token is stale.

A matching prepared revision resumes through its fresh `session.begin` template; a running session resumes at the earliest unproven phase only when the active procedure ID, canonical task identity, goal revision, and current node agree. A recorded plan handoff also requires the exact artifact checks in the shared reference. Otherwise stop rather than repairing history by inference.

Resume at the earliest phase whose postcondition is not currently proven. Preserve the same frozen Low set and reuse completed verified dispositions; process only the remaining items. Do not reset review ordinals, create a replacement session, or repeat review or settlement merely to recreate a report. Invalidate only evidence affected when task-owned code, tests, documentation, roadmap state, review target, or repository authority changed after it was recorded.

On the Podway path, when only finalization remains after a verified accepted commit or permitted no-commit result, resume the shared finalization steps without repeating the proven leaf closeout or commit.

## Report Orchestration State

Keep progress updates concise. At every stop and final handoff, report the completed phase, next phase, task-owned paths, current roadmap status, release-note target and decision, agent-run and user-run checks, staged and unstaged state, review route, operation, evidence reference, provenance, backend-check result, findings status, goal state, and any remaining commit or publication gap. On the Podway path, include the shared finalization report fields and distinguish repository completion from pending session finalization. A plan handoff must also report every session and artifact identity required by the shared reference.
