# Changelog

This file records concise shipped outcomes of the Aquarium for Claude edition. Releases before v0.1.14 are recorded in this repository's Git tags and GitHub releases; upstream outcomes live in the [Aquarium changelog](https://github.com/irootkernel/aquarium/blob/main/CHANGELOG.md).

## v0.1.15 - Unreleased

### Added

- Guard the plugin root in both directions. `COPIED_DIRECTORIES` grew a counterpart check when `hooks/` was dropped in silence, but that check filtered on directories and nothing copies a plugin-root file at all, so v0.1.15's new `.mcp.json` would have vanished exactly the same way. Generation now aborts on an unhandled plugin-root file as well as an unhandled directory, records each deliberate plugin-root exclusion with the reason it does not belong in a Claude Code artifact, requires the target to still exist upstream, and `tests/validate.rb` reads that list out of `scripts/sync.py` so an exclusion retired there stops being tolerated here in the same commit.
- Cover the skill roots the shipped inspector actually searches. The MCP inspection tests were the only executable coverage of the generated script, and they said nothing about where it looks for skills; a new class asserts the configured root wins, that no other host's root is searched, and that both writing skills are expected in the effective Claude Code root.
- Record the plugin-root exclusions in `sync-manifest.json`. The manifest is the artifact's own account of the transformation and was under-reporting by the two entries the new table holds; the validator now compares that list with `scripts/sync.py` as well.

### Changed

- Adopt upstream Aquarium v0.1.15: user-global installation split into the new `dev-setup-global` skill, the shared tool catalog moved into the plugin's own `references/`, Sorage setup, Dolgorae v0.1.2 with global Profiles, Mulgae v0.1.19 with command-result v6, Gaori v0.1.16 with the optional `use-gaori-status` skill, Podway v0.2.9, Gaori and Mulgae asynchronous lifecycles delegated to their upstream skills, agent guidance reorganized around seven core behaviors, and release-QA confirmation integrity.
- Exclude the bundled development channel whole. Upstream replaced the `aquarium-dev` skill with a Darwin arm64 CLI and stdio MCP runtime under a plugin-root `tools/` directory, registered from a plugin-root `.mcp.json` in the other host's `mcp_servers` shape. It builds unreleased local-main artifacts of Aquarium and its producer CLIs under `~/.aquarium-dev`, passes `CODEX_HOME` through to them, and produces Codex plugin artifacts; no skill here routes through it, its hash-pinned wheel lock would ship dead weight, and a translated registration would start a server no installation provides and report a failed MCP connection in every session of every repository. Its shared producer contract is excluded with it, and the two `Codex` exemptions the retired skill carried are retired rather than rotated.
- Shrink the global inspector's Ouroboros component to the one installation this host has. Upstream's `inspect_ouroboros.py` measures per-Codex-home rules, skills, and MCP registration by importing `ouroboros.codex.artifacts` and comparing each discovered home, none of which exists here, so that module is excluded and the component now calls the project inspector's plugin-scoped probe instead. The per-home options leave the signature, the parser, and the call site together, so the generated-script arity gate proves no caller was left behind.
- Retire the `dev-setup` override. Upstream's split moved every user-global divergence into `dev-setup-global`, leaving three literal spans — two of which carry a forbidden needle and would need a rule whether or not the override stayed — so the cost ladder puts them back on substitutions. The counted swaps were proved to reproduce the retired override byte for byte before it was deleted, and `dev-setup-global` becomes the fifth override in its place.
- Collapse six Ouroboros block rules into one whole-function rule. v0.1.15 left every one of their opening lines in place and changed the lines around them, which is the stale-anchor case a block rule cannot distinguish from a live one; a whole function is the most stable anchor upstream offers and fails loudly instead of drifting.
- Scope the no-hard-wrap convention to the Markdown this repository writes. It is this repository's convention, and v0.1.15 shipped two hard-wrapped upstream references, so the check now covers the repository's own documents plus the override and addition sources — which is where every generated file this repository authors comes from byte for byte — rather than upstream's prose under upstream's style.

### Fixed

- Route Ouroboros, Deslop, and Lora to the skill that now owns them. Upstream's split moved user-global installation into `dev-setup-global`, and both READMEs still told a reader whose design skills were blocked on a degraded Ouroboros to run the one skill that no longer looks at it. The shipped repository skill mentions none of the three.
- Stop claiming an MCP registration shape check the shipped classifier does not perform. `claude mcp get` prints a scope and a status rather than the transport fields upstream compares, so a hand-registered entry that connects is a configured registration with the integration still unverifiable — which the catalog now says instead of promising a comparison the inspector cannot make.
- Close the loop between the prescribed Ouroboros configuration action and the migration rule that would have flagged its own output. A copy the full setup installs or prunes for the selected runtime belongs to that action and is never a migration candidate.
- Stop failing global readiness closed on a binary this edition never uses. Dolgorae joins Sanho outside the production-binary baseline, matching the shared catalog, which already reports it as third-party readiness because no skill here routes a review through it.
- Diagnose paired and third-party skills against the root this host loads. v0.1.15 hard-coded the shared cross-agent root for eleven skills in a new presence-only trust table, and again in the Lore and Deslop readiness comparisons, against an inspector this edition narrows to the Claude Code roots — so every correct installation would have reported degraded forever, the same failure the writing skills had in v0.1.14. The forbidden needle never saw any of it because it carried a leading tilde the Python spelling does not, so the needle is now the spelling both languages share and all three sites resolve through the effective Claude Code skill root.
- Follow upstream's own retirement of the goal-mirroring instruction. The rule that named this host's todo list survived on a sentence v0.1.15 rewrote to couple the host goal to an explicit request, so naming the mechanism would now contradict the contract it was written to serve.

## v0.1.14 - 2026-09-04

### Added

- Add the edition-owned `/aquarium:upgrade` skill: one full upstream release adoption run as an orchestrated lifecycle — Opus and Sonnet subagents gather the delta and apply approved re-derivations while the invoking conversation decides, reviews, and validates — ending in the reviewed tag, GitHub Release, and local installation refresh behind explicit approvals, with `references/rederivation.md` recording the counted-swap method and the known adoption traps.
- Teach the generation and validation to carry edition-owned skills: `additions/skills/**` ships through the `ADDED_PATHS` allowlist, generation refuses a skill addition that does not declare its own model-invocation gating, and the validator asserts the generated skill set is upstream plus the recorded additions.
- Own the repository-state inspector `independent-review` runs for its no-mutation baseline. Upstream shipped it beside `orca-review` and removed it in v0.1.14; it is now an edition addition under the skill that calls it, which also retires the cross-skill path nothing in the sync watched.
- Name the shell variables the sigil scan cannot tell apart from skill invocations. `task-commit` pins the commit identity through `git -c user.name="$aquarium_commit_name"`, so generation carries an explicit exception list, requires each entry to still occur upstream, and compares it with the validator's copy as a set rather than narrowing the pattern and admitting every future `$snake_case` skill.

### Changed

- Adopt upstream Aquarium v0.1.14: the `aquarium-dev` development channel, official Dolgorae v0.1.1 support, exact-upstream Humanizer and im-not-ai installation, the shared finding-disposition contract, dossier-scoped epic execution, Podway v0.2.8, and repository-local commit identities.
- Keep independent review on host subagents where upstream moved it onto a Dolgorae immutable capture running a fresh Codex Reviewer. `references/review-contract.md` becomes the fifth override so the scope table, backend ownership, settlement, and result envelope describe the backend this artifact actually has; the two capture-only scopes are unsupported for the same reason they are unsupported for Orca Review, and the excluded Dolgorae consumer contract documents a lifecycle this edition does not run. Two shipped references that still described the upstream backend are corrected in place: `orca-review` no longer refers a caller to independent review for scopes neither backend supports here, and the shared disposition contract no longer groups independent review with the backends that capture.
- Install and diagnose Humanizer and im-not-ai on this host rather than another. im-not-ai's own installer has a first-class Claude mode that materializes a different payload — three skills and four subagents rather than one skill — so `dev-setup` discloses that command and compares that tree, and the generated inspector expects both skills in the Claude Code skill root instead of the shared cross-agent root and the Codex home, where every correct installation would have reported degraded forever.
- Follow upstream in opening `orca-review` to implicit invocation: naming both a review target and a reviewer is now itself the request, as it already was for a commit request and `task-commit`.

### Fixed

- Stop naming a host tool that no longer exists. `release-qa` and the `upgrade` skill named the Task tool as this host's dispatch surface; Claude Code has since renamed it, so both now name the subagent mechanism instead, and the re-derivation notes record tool names in replacement text as a standing rename risk.
- Give the mandated review-target inspector its exact invocation form, name what its `commit` digest actually covers for a merge, and stop the shared contract from denying the snapshot and digest evidence the skill's own inspectors produce.
- Diagnose and install user-scoped skills against the configured Claude Code skill root rather than a hardcoded `~/.claude/skills`, so a `CLAUDE_CONFIG_DIR` user is not told to install where the inspector will not look.
- Add `head` to the bundled reviewer's authorized targets, scope the oversized-report filesystem exception to the Orca lifecycle that grants it, and report the Dolgorae dimension the inspector actually produces.
